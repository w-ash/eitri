# Bambu Lab X2D

What an agent needs about the Bambu Lab X2D, its accessories and Bambu Studio, without searching the web.

Sources: the X2D User Manual v1.0, 2026.05 ([PDF](https://csm.bblcdn.com/hub/7c58718aaa2e40edab56efb87419a96a.pdf)), cited "manual §x.y". Bambu Studio 02.09.01.70's bundled profiles (the installed app, `Contents/Info.plist`), cited by path under `/Applications/BambuStudio.app/Contents/Resources/profiles/BBL/`, with values taken from the flattened chain. Bambu Studio's C++ source at tag v02.08.02.61, cited by file and line. "Tested" means a try with Bambu Studio on macOS, usually a command-line slice, cited "(tested <date>)"; with no date, 2026-10-24. Joints and PLA Pure strength are in [joining-printed-parts.md](joining-printed-parts.md).

The user's own printer setup (nozzles, plate, AMS inlet, filaments) and open questions about it belong in `projects/CLAUDE.md`.

## The X2D for design

- Two hotends on one toolhead. The main hotend is on the left, direct drive, with its extruder in the toolhead. The auxiliary hotend is on the right, Bowden, with its extruder on the rear panel (manual §1.2.2, §6.1). `extruder_type` is ["Direct Drive","Bowden"] (`machine/Bambu Lab X2D 0.4 nozzle.json`).
- CoreXY ([Memory Express](https://www.memoryexpress.com/Products/MX00136904)), with a bed that moves only in Z (manual §7.2.3). So travel doesn't shake a tall part: the risk is nozzle drag, or the nozzle catching a curled edge (inference). Z-hop is Auto Lift, 0.4 mm (sliced config).
- Print areas (manual §6.2.1; `extruder_printable_area` and `extruder_printable_height` in the same profile):

  | Hotend | XY | Height, manual | Height, profile |
  |---|---|---|---|
  | Main | x 0–256, y 0–256 | 260 | 261 |
  | Auxiliary | x 20.5–256, y 0–256 (235.5 × 256) | 256 | 256 |

- Conflict: the manual gives 260 mm, while the profile's `printable_height` is 261. The repo uses 260 (`justfile`, `bed`).
- Only the main hotend reaches the left 20.5 mm strip, which Bambu Studio shades as "Left nozzle only area". All filaments of a model placed partly in that strip, or taller than 256 mm, print on the main hotend. A Custom grouping that sends such a model to the auxiliary hotend is a slicing error (manual §6.2.1).
- `just check` prints a NOTE that only the main hotend can print a model wider than 235.5 mm or taller than 256 mm. `just slice` keeps any other model out of the strip (`justfile`; see Placement below).
- The auxiliary hotend can't print PLA Aero. Use it with caution for PLA Silk, PETG-CF, ASA-CF, PA6-CF, TPU for AMS and Support for PA/PET, and with a 0.2 mm nozzle; PLA-CF isn't on that list (manual §8.2, pp. 107–108).
- A second nozzle doesn't speed up a one-material part. "The main nozzle prints the part. The auxiliary nozzle handles the support" ([X2D](https://bambulab.com/en-us/x2d)), and for single-color prints Bambu recommends the fixed hotend ([Bambu store](https://us.store.bambulab.com/products/bambu-hotend-h2-p2s)). The auxiliary hotend's speeds are lower: outer wall 50 vs 200 mm/s, sparse infill 200 vs 270 mm/s (`process/0.20mm Standard @BBL X2D.json`).
- In the box: a standard 0.4 mm hardened steel hotend on each side (manual §1.2.2, §8.2) and a second-generation Textured PEI Plate (manual §2.1.2, §6.4.2). The filament track switch, TPU feeding assist module, AMS HT, High Flow hotend and other plates are optional (manual §1.1).
- Startup line: after bed leveling, the start G-code runs `G0 X100 Y0`, then `G130 O0 X100 Y-0.2 Z0.6 … L40` (`machine/Bambu Lab X2D 0.4 nozzle template machine_start_gcode.json`). Reading `L40` as the line's length puts the line along the front edge at x 100–140, y ≈ 0, so keep parts off that strip (inference).
- Layer heights (`min_layer_height`, `max_layer_height` and `default_print_profile` in `machine/Bambu Lab X2D <d> nozzle.json`; the 0.4 nozzle's limits come from `fdm_bbl_3dp_002_common.json`):

  | Nozzle | Layer, mm | Default process |
  |---|---|---|
  | 0.2 | 0.04–0.14 | `0.10mm Standard @BBL X2D 0.2 nozzle` |
  | 0.4 | 0.08–0.28 | `0.20mm Standard @BBL X2D` |
  | 0.6 | 0.12–0.42 | `0.30mm Standard @BBL X2D 0.6 nozzle` |
  | 0.8 | 0.16–0.56 | `0.40mm Standard @BBL X2D 0.8 nozzle` |

- Each of these four profiles gives both hotends the same nozzle diameter. The thickest 0.4 nozzle preset is `0.24mm Standard @BBL X2D`, so for 0.28 mm layers, edit its layer height (`process/`).
- Filament grouping modes, chosen by hovering over Slice (manual §6.2.3):
  - Filament-Saving, the default, minimizes purging. Sync the AMS-to-hotend pairing first. After slicing, each filament is bound to one nozzle and the printer can't switch it.
  - Convenience follows the actual AMS placement after a sync.
  - Quality: when a different filament prints the support or raft interface, the auxiliary hotend prints the interface and the main hotend prints the model body.
  - Custom: drag each filament to a nozzle.
  - CLI `filament_map_mode`: "Auto For Flush", "Auto For Match", "Auto For Quality" or "Manual" (strings in the binary, tested). These are Filament-Saving, Convenience, Quality and Custom (inference from the names).
  - For a one-filament print in the app, Convenience makes the slice follow the AMS placement instead of the CLI's "Auto For Flush". Advice from §6.2.3, not tested.
- AMS: on the filament buffer, the upper inlet feeds the main (left) hotend and the lower inlet feeds the auxiliary (right) hotend. Bambu recommends putting AMS units on the main hotend (manual §1.2.1, §2.2.1, §2.7). Each hotend takes up to 4 AMS 2 Pro units, and 3 or more units need a 4-in-1 PTFE adapter (manual §2.7). The optional filament track switch lets any AMS feed either hotend (manual §6.6.1).
- PETG Matte was missing from the printer's filament list on 2026-11-02 (firmware version not found). It launched in October 2026, and an X1C owner reports the same ([forum](https://forum.bambulab.com/t/petg-matte-is-here-prints-like-pla-lasts-like-petg/260388?page=2)); no firmware note names it. Older X2D firmware refused PETG on the auxiliary hotend, and an update allowed it with a quality warning ([forum](https://forum.bambulab.com/t/confused-on-using-petg-in-x2d-on-aux-nozzle/250170)). Until it's listed, set the slot to another PETG: the print's temperatures and speeds come from the sliced file (inference).
- AMS auto refill: turn on Settings → AMS Options → "AMS Auto-Refill" ([AMS 2 Pro wiki](https://wiki.bambulab.com/en/ams-2-pro/manual/setup-and-printting)). It refills only from a spool of the same brand, type and colour on the same hotend, and Bambu PLA Pure and PLA Basic are different types (Studio's filament table: GFA19, GFA00). The X2D refuses a refill group that mixes them: it requires the same brand, colour and type (seen on the printer, 2026-11-04). Without a match, the print pauses at run-out and keeps its progress: load the slot and press Retry ([HMS 0700_2000_0002_0001](https://wiki.bambulab.com/en/x1/troubleshooting/hmscode/0700_2000_0002_0001)). Both X2D 0.4 profiles print at 220 °C with flow 0.98, so a swap mid-print keeps the same settings.
- Plate check: the printer photographs the plate and checks that its type matches the slice (manual §6.4.2). `machine/Bambu Lab X2D.json` sets `default_bed_type` to "Textured PEI Plate" and `not_support_bed_type` to "Cool Plate".
- Speed modes on the printer: Silent 50%, Standard 100%, Motion 124% and Ludicrous 166% of speed and acceleration (manual §7.1.1). A forum calls the 124% mode "Sport" ([Bambu forum](https://forum.bambulab.com/t/print-speed-setting/135942)).
- Limits: nozzle 300 °C, bed 120 °C, and the chamber heats to 65 °C (manual §1.1).

## PLA Pure

Profile `filament/Bambu PLA Pure @BBL X2D 0.4 nozzle.json` (setting_id GFSA19_34), with the chain `Bambu PLA Pure @base` ← `fdm_filament_pla` ← `fdm_filament_common`. The 0.2, 0.6 and 0.8 nozzles each have their own PLA Pure file.

- Nozzle 220 °C, first layer included. The profile's range is 190–220 °C; the data sheet gives 190–230 °C and a bed of 35–65 °C ([TDS](https://store.bblcdn.com/s7/default/18f44e818d5f41ed8876364ecbb7af8d/PLA_Pure-TDS.pdf), settings review, 2026-11-02).
- Flow ratio 0.98. Max volumetric speed is 12 mm³/s for every nozzle and hotend variant, which caps print speed (`filament_max_volumetric_speed`).
- Bed: 55 °C on Textured PEI (`textured_plate_temp`, from `fdm_filament_pla`) and 35 °C on Cool Plate. The sliced G-code shows `M190 S55` and `M190 S35` (tested).
- Minimum layer time is 8 s, which slows printing to no less than 20 mm/s (`slow_down_layer_time`, `slow_down_min_speed`), and density is 1.24 g/cm³ (`Bambu PLA Pure @base`).
- Circle compensation (`enable_circle_compensation`) supports only PLA Basic, PLA CF, PET CF, PETG CF and PETG HF, so not PLA Pure (PrintConfig.cpp:6066, v02.08.02.61).
- Strength is 75 MPa XY and 55 MPa Z in bending. Keep parts under 60 °C (Bambu store, in [joining-printed-parts.md](joining-printed-parts.md)).
- Vertical clearances must be more than one layer. At 0.28 mm layers, a 0.2 mm gap sliced to zero over 22–27% of its area, and 0.3 mm always cleared (tested 2026-10-24, G-code analysis).
- At 2 walls and 10% infill, keys, bosses and loops print as two loops around a sparse core (tested 2026-10-24).

## Supports

- A flat overhang needs supports past about 2 mm. Bambu: an overhang supported at one end "must be supported, even if it's small" ([Support wiki](https://wiki.bambulab.com/en/software/bambu-studio/support)). PLA Basic: max overhang 55°, max bridge 30 mm ([data sheet](https://wiki.bambulab.com/filament-acc/abs-asa-pc/bambu_pla_basic_technical_data_sheet.pdf)). Maker tests on other printers: quality declines from 2 mm ([Fab Academy](https://fabacademy.org/2024/labs/reykjavik/assignments/week05.html)), and "2-3mm is maximum unsupported overhang" ([MIT 863](https://fab.cba.mit.edu/classes/863.25/EECS/Week3.html)). So a horizontal ledge 3.5–4 mm wide, ringed round a post 30 mm up, gets supports (inference).
- Settings for that ledge, with support from the bed only (Support wiki; [PLA Pure guide](https://wiki.bambulab.com/en/filament/pla-pure); tested 2026-10-29): `enable_support` 1, `support_type` normal(auto), `support_style` snug, `support_on_build_plate_only` 1, `support_interface_top_layers` 3. Normal is better than tree for large flat overhangs (Support wiki).
- Supports in the same PLA need no special filament. Set `support_top_z_distance` to about 0.2, not 0 (Support wiki). At 0.12 mm layers, set the top and bottom Z distance to 0.12, as "0.12mm High Quality @BBL X2D" does (`tools/bambu-profile`). Only an interface in a dedicated filament (Bambu Support for PLA, or PETG for PLA) gives a face without sag at top Z 0 (Support wiki; [forum](https://forum.bambulab.com/t/is-the-specialty-support-filament-worth-it/61694)).
- Same-PLA support under a 3.6–4.1 mm ledge, at 0.12 mm layers with a 0.12 mm top gap and 3 interface layers, was almost impossible to remove (fit test print, 2026-10-30).
- Two-filament slicing from the command line works once each filament has a colour (tested 2026-11-02). Without `filament_colour`, Bambu Studio 02.08.02.61 exits 139: the flattened system profiles and a bare OpenSCAD 3MF carry no colours, so the flush matrix is empty, and `FilamentGroup::calc_one_change_budget` reads through a null pointer when two filaments are in use (macOS crash report; ToolOrdering.cpp `prepare_flush_matrices` ~1562, FilamentGroup.cpp 229–244). The log line "no filament colors found in projects" marks it. To slice two filaments:
  - Add `"filament_colour": ["#RRGGBB"]` to each filament JSON, or pass `--filament-colour "#…;#…"`.
  - Put the prime tower on the bed: the default `wipe_tower_x` 15, `wipe_tower_y` 220 fails with -104, "G-code outside of the printable area". `wipe_tower_x` ["180"], `wipe_tower_y` ["200"] put it at x 178–222, y 198–241 for a model centred on x 138.25.
  - Pass `--filament-map-mode "Auto For Quality"` (or `Manual` with `--filament-map "1,2"`) on the command line. Set only in the process JSON, the config shows it but the G-code is grouped "Auto For Flush". With Auto For Quality, a support-interface filament 2 printed only on the auxiliary (Bowden) hotend (`; filament_map = 1,2`, `Metadata/slice_info.config`).
  - Use a bare 3MF as the input. A one-filament Bambu 3MF fixes the filament count at 1 and fails with -100.
  - `just slice` takes one filament. A PLA model with a PETG Matte interface on the auxiliary hotend was sliced this way (tested 2026-11-02).
- The bed heats to `bed_temperature_initial_layer_single`, which comes from the filaments on the first layer. With PLA Pure on the first layer and PETG Matte (Textured PEI 70 °C) only higher up, the bed stayed at 55 °C, so set a filament's bed temperature in that filament's JSON (G-code, 2026-11-02; GCode.cpp `get_highest_bed_temperature`).
- Bambu Studio's own recommendation for a PLA model with a PETG interface, which the app offers on the X2D when the interface filament is picked: tree(auto) hybrid, top Z 0, `support_interface_spacing` 0, rectilinear_interlaced, `support_interface_speed` 50 (`Resources/profiles/BBL/filament/support_recommended_params.json`; Tab.cpp ~2420–2600, settings review). The first layer over an interface prints as a bridge even at top Z 0 (PrintObject.cpp 1492), so `bridge_flow` above 1 presses into the interface; Bambu's PETG→PLA presets use 1.
- Keep the prime tower with two filaments on the two hotends. Nothing is flushed (each filament stays in its own nozzle), but the tower rebuilds pressure in the nozzle that was idle. On the X2D, Bambu Studio warns that a model "would not print correctly" without it, and the auxiliary hotend's Bowden extruder needs extra time to build pressure, so a small support interface may be mostly missed ([forum 261412](https://forum.bambulab.com/t/x2d-and-the-purge-tower/261412), [forum 251866](https://forum.bambulab.com/t/is-the-x2d-right-for-pla-petg-support-only/251866); users, not Bambu). H2D users without a tower saw the swapped-in nozzle miss the start of its lines ([forum 162114](https://forum.bambulab.com/t/h2d-printig-supports-without-prime-tower-problem/162114)). One X2D user cut the prime volume below 40% of the default without visible defects (forum 261412). Official Bambu guidance for the X2D: not found; the manual names the tower only for timelapse smooth mode (§ on timelapse) and plate cleanup.
- A CLI two-filament 3MF reopened in the app: the plate keeps `filament_map_mode` "Auto For Flush", and filament keys not named in `different_settings_to_system` reset to the system preset (settings review; Preset.cpp 2258–2269). Print it as sliced, or choose the grouping again before re-slicing.
- Bambu's mutual-support guide (https://wiki.bambulab.com/en/filament-acc/filament/h2d-pla-and-petg-mutual-support) covers PLA Basic with PETG HF or PETG Basic only, as interface only: PLA 230 °C, PETG HF 265 °C or PETG Basic at default, PETG at 10 mm³/s, bed 60 °C, door or top cover open. Its preset: top and bottom Z 0, interface spacing 0, 3 interface layers, rectilinear_interlaced, XY distance 0.35, `support_interface_not_for_body` 1, flush into support only. Bambu's PETG Matte page says "PETG Matte is not recommended as a support for PLA. For multi-material support, use Bambu PETG Basic" (https://eu.store.bambulab.com/en/products/petg-matte). The X2D profile for Bambu Support For PLA-PETG is named "Bambu Support For PLA/PETG @BBL X2D 0.4 nozzle"; it prints at 210 °C, max 6 mm³/s (`tools/bambu-profile`).
- Normal is better than tree under a large flat overhang (Support wiki), and users with a PLA/PETG interface report the same (forum threads 165269, 61694). On a ledge ring round a tall tapered point, tree slim with `support_critical_regions_only` 1 stayed under the ledge but laid about an eighth of normal snug's interface line under the point (G-code, 2026-11-02). Every tree style without that key grew into the eye slot.
- With `tree(auto)` and build-plate-only, the slicer still grew branches up to a round horizontal finger hole in a vertical tab, with support to z 65 mm. A teardrop hole (BOSL2 `teardrop2d(d=, cap_h=)`) stopped it. With normal(auto), support stayed under the ledge only (tested 2026-10-29). Tree branches also climbed through a through-slot open at the sides, to z 193 (tested). To see where support lands, see Inspecting a sliced 3MF below.
- With the same-PLA settings above, the gap under the face measured 0.2 at 0.24 mm layers and 0.12 at 0.12 mm, and the first layer of the face printed as Bridge, at `bridge_speed` (G-code, 2026-10-29). With `independent_support_layer_height` 1, the default, support layers print about 0.28 mm thick, but the gap holds. For a smoother face, turn on `enable_support_ironing` (Develop mode) and raise the top Z distance slightly ([PLA Pure guide](https://wiki.bambulab.com/en/filament/pla-pure)).
- Support on the first layer removes the brim wherever it lies (Brim.cpp `top_level_outer_brim_area`, v02.08.02.61). Normal snug support under a collar made a solid first-layer ring round a 21.5 mm foot, and no brim printed at `brim_width` 3, 8 or 15, with auto, or with painted ears. With support off, auto gave about 16 mm for a 233 mm part and 10 mm for a 182 mm one (tested 2026-10-29; other styles not tested). So check for `; FEATURE: Brim` lines (Inspecting a sliced 3MF), and for a tall part on a small foot plan glue (manual §9.3.2) or a model change.

## Bambu Studio: opening an OpenSCAD 3MF

- `open -a BambuStudio <file.3mf>`. Bambu Studio asks which filament to use, and for a project 3MF, whether to keep the project's presets. It shows no orientation or units dialog (tested 2026-10-24).
- "The 3mf file has invalid config, load geometry data only" is harmless ([openscad-toolchain.md](openscad-toolchain.md)).
- Before slicing, select the printer and build plate, then Sync info pulls the nozzle and AMS data from the printer (manual §4.2.3, §5.1.2).

## Bambu Studio from the command line

`just slice <name> [set]` wraps this (`justfile`). It runs `check` first, so a model that fails the min-z or size gate isn't sliced, then writes `out/<name>/<stem>-print.3mf`, `<stem>-plate.png` and `<stem>-settings.json`, and prints the print time, grams, layer height and plate. The justfile's `bambu_app` names the app, `/Applications/BambuStudio.app`: the binary is `Contents/MacOS/BambuStudio` inside it, and `tools/bambu-profile` reads the same app's profiles. Every CLI option, the official docs, and what `slice` does with each: [bambu-studio-cli.md](bambu-studio-cli.md).

- Set names: `print`, and any set ending in `-print`, are reserved, since `slice` writes `<stem>-print.3mf`. `build` refuses them (`justfile`).
- `just check-all` checks every model and set in a temporary folder that it removes on exit. It never changes `out/`, so it leaves the `-print.3mf` files there alone, and it writes no renders (`justfile`, tested).
- Profiles: flatten each system profile into one JSON, then pass the files (see the last section). Keep `name` and `from` unchanged. Setting `from` to User, or renaming the profile, gave "process not compatible with printer" (error 3002, return_code -17) (tested 2026-10-24).
- Resolve `include` as well as `inherits`. Without the includes, the slice uses generic G-code. A slice made that way had the start G-code from `fdm_machine_common.json` (prime line at x 10, y 20–200, `M109 S205`) and its other G-code blocks from `fdm_bbl_3dp_002_common.json` (tested). To check a slice, `grep -c '^ *G130'` on its G-code should give 1. With the includes merged, the G-code has the X2D start and its `G130` line (tested).
- Command, run from the output folder: `BambuStudio --arrange 0 --load-settings "machine.json;process.json" --load-filaments filament.json --slice 0 --outputdir <dir> --export-3mf <name>.3mf <input.3mf>` (tested 2026-10-24). It writes `<name>.3mf`, `plate_1.gcode` and `result.json` (`return_code`, `error_string`, time per feature) to `--outputdir` (tested).
- Working folder: a slice got "Unable to open the file <name>.3mf.tmp" (exit 243) when it didn't run from the output folder. With an absolute `--outputdir`, running from another folder worked (tested). Even `--help` writes a `result.json` into the working folder (tested), so run from the output folder and never from the repo. `just slice` runs in a `mktemp -d` folder under `$TMPDIR`, which is both its working folder and `--outputdir`, and removes it on exit (`justfile`).
- Placement: OpenSCAD centers models on the origin. With auto-arrange, a bed-filling piece failed with "no object fully inside the print volume" (-50). Translate the model onto the bed and use `--arrange 0` (tested 2026-10-24). `just slice` centers a model 235.5 mm or narrower and 256 mm or shorter on x 138.25, the middle of the auxiliary hotend's x 20.5–256, so it stays out of the main-only strip. It centers a wider or taller model on x 128. Y is 128 for both (`justfile`). A 225 mm part sliced at x 25.75–250.75, and a 245 mm part at x 5.5–250.5 (tested, `Metadata/plate_1.json` and the G-code).
- Overrides: `just slice` merges the values in `projects/<project>/<model>.slice.json` over the process preset, each written as a string. After slicing, it compares each requested value with the sliced 3MF's `Metadata/project_settings.config`, and fails, naming the key, when one is missing or different (`justfile`). A filament key doesn't take effect through the process profile: `nozzle_temperature` 230 left PLA Pure's 220 in the config, and the slice failed. `layer_height` 0.28 took effect. A per-extruder process key set to one value becomes a one-item list: `outer_wall_speed` 150 became `["150"]`, which the check accepts (all tested). The preset's lists hold six values, in `print_extruder_variant` order: three for the main (Direct Drive) hotend, then three for the auxiliary (Bowden). Which value the auxiliary hotend gets from a one-item list: not tested. A full six-item list takes effect and passes the check (tested 2026-10-29).
  - The reserved key `"cli"` holds other Bambu Studio options, such as `["--rotate", "90"]`. `just slice` passes it after its own options, after checking each against `--help`, and keeps it out of the process profile ([bambu-studio-cli.md](bambu-studio-cli.md)).
  - The app keeps only listed overrides. On opening a 3MF, it resets every process key not named in `different_settings_to_system[0]` to the system preset (PresetBundle.cpp `load_config_file_config` ~3768–3885, Preset.cpp `load_external_preset` ~2258–2269, PrintConfig.cpp `update_non_diff_values_to_base_config` ~9266). With the keys listed, the app showed the `.slice.json` values (tested 2026-10-29).
  - The list: index 0 is the process, 1..N one entry per filament, and the last is the printer. Each entry is a `;`-joined key list.
  - The CLI copies `different_settings_to_system[0]` from the `--load-settings` process JSON into the 3MF when the input isn't a Bambu 3MF (BambuStudio.cpp ~2382, ~3202). So `just slice` writes the `.slice.json` keys there (`justfile`, commit d930a87). Without them, a sliced 3MF opened in the app showed support disabled, though its stored G-code had supports (tested 2026-10-29).
  - Per-object `<metadata key=… value=…/>` under `<object>` in `Metadata/model_settings.config` also takes effect, but shows as per-object settings (bbs_3mf.cpp ~2242).
- Defaults unless the process JSON sets them: `curr_bed_type` Cool Plate (`M190 S35`), `brim_type` auto_brim, and `filament_map_mode` "Auto For Flush" (tested).
- `just slice` gives the filament a colour, black by default (`filament_colour` "#000000"), and pins it to the main hotend: `--filament-map-mode Manual --filament-map 1`, plus the plate's `filament_map_mode` set to Manual in `Metadata/model_settings.config`, which the CLI leaves at "Auto For Flush" (tested 2026-11-06). Without these, a 3MF opened in the app showed the default green and was regrouped onto the auxiliary hotend (tested 2026-11-06). Override with `just --set filament_colour "#…"` or `--set hotend 2`.
- Values that work: `curr_bed_type` "Textured PEI Plate" (gives `M190 S55`, tested); `brim_type` no_brim; `ensure_vertical_shell_thickness` partial; `sparse_infill_pattern` adaptivecubic; `wall_loops` 3 (tested 2026-10-24, all in one sliced 3MF's config). The binary also names Cool Plate, Engineering Plate, High Temp Plate and Supertack Plate (`strings`, tested).
- Fine finish: `just slice` always starts from "0.24mm Standard @BBL X2D", so a model that needs one copies these keys from "0.12mm High Quality @BBL X2D" into its `.slice.json`, each per-extruder key as the preset's full list: `layer_height` 0.12; `outer_wall_speed`, `inner_wall_speed`, `outer_wall_acceleration` and `default_acceleration`; `bridge_speed` and `bridge_flow`; `sparse_infill_speed`, `internal_solid_infill_speed` and `top_surface_speed`; `bottom_shell_layers` 5; and the support top and bottom Z distances, equal to the layer height (`tools/bambu-profile`). Before that, inner walls ran at about 235 mm/s and 10000 mm/s² (G-code). A fit test sliced at 0.24 mm for a 0.12 mm model ran its outer wall at 136 mm/s instead of 60, and its support gap at 0.2 instead of 0.12 (G-code, tested 2026-10-29). For the preset's other differences, diff the two flattened profiles with jq.
  - Round walls: add a scarf seam, which "in most cases can reduce the visibility of seams" ([Seam wiki](https://wiki.bambulab.com/en/software/bambu-studio/Seam)): `override_filament_scarf_seam_setting` 1 and `seam_slope_type` external. `seam_slope_type` alone changed nothing, since PLA Pure's `filament_scarf_seam_type` is none (tested 2026-10-29). Keep `seam_position` aligned (random leaves zits, Seam wiki) and the inner/outer wall order, which prints overhangs better ([Quality wiki](https://wiki.bambulab.com/en/software/bambu-studio/parameter/quality-advance-settings)). Smoothing outer-wall speed along Z is already on (`z_direction_outwall_speed_continuous` 1).
  - On a 182 mm point the set added 8% to the time, mostly from the scarf seam (tested).
  - Round parts that narrow upward: set PLA's `no_slow_down_for_cooling_on_outwalls` ["1"] in the
    filament JSON. Otherwise the 8 s minimum layer time slows the outer wall toward 20 mm/s on the
    small top layers, the speed range where vertical fine artifacts (VFAs) form; the key's tooltip
    names them (PrintConfig.cpp:1815, v02.08.02.61). It is a filament key, so `.slice.json` can't
    set it, and the app resets it on opening. With it, a tall tapered point's outer wall held 60 mm/s
    up to the tip (G-code, 2026-11-04).
  - Mesh round parts finely in OpenSCAD: `$fa` 0.5 and `$fs` 0.15 give about 700 segments on a
    33 mm circle. Bambu Studio's `resolution` 0.012 then keeps about 144 segments per loop at
    r ≈ 16 mm, a chord error of about 4 µm, which is enough. A 180-segment mesh printed with only
    56 per loop. A plate of a few million facets makes OpenSCAD print "Node didn't fit into
    cache" (3.33 million did, tested 2026-11-04): the command
    line's geometry cache is a fixed 100 MiB (`GeometryCache.h:13`) and the warning is only a
    failed cache insert (`GeometryEvaluator.cc:359-360`). `tools/openscad` lets that one line pass,
    so a large plate builds and checks; it costs build time, not correctness
    (research, 2026-11-04).
- Arc fitting: keep `enable_arc_fitting` 0 on the X2D. Its firmware (01.01.00.00 and later) does
  its own curve planning, and Bambu Studio 2.9.1 sets arc fitting 0 for printers with it (Bambu
  Studio commit d225c9a1df; X2D firmware release history on the Bambu wiki).
- Lighter parts: `sparse_infill_pattern` lightning holds up only top surfaces. At 8% it cut a plate of 8 tall round parts from 398 g to 258 g, and a plate of 8 tapered points from 213 g to 135 g. With lightning, walls were about 80% of a tall part's filament; at 8% grid, infill was 37% (tested 2026-10-29). Lightning leaves loose strands inside. For fewer, use support cubic at 10% (strongest saving; it fills densely only under top surfaces) or grid at 10%.
- Inspecting a sliced 3MF:
  - Settings: `out/<model>/<stem>-settings.json`, which `just slice` writes with `--export-settings`. It matches `unzip -p f.3mf Metadata/project_settings.config` except for `extruder_nozzle_stats_new` (tested 2026-11-04).
  - Objects as loaded: `<stem>-plate.png`, Bambu Studio's own Iso picture of plate 1. It shows the objects but not the bed or supports, so placement comes from `Metadata/plate_1.json` and the G-code (tested 2026-11-04).
  - Brim lines: `unzip -p f.3mf Metadata/plate_1.gcode | grep -c '^; FEATURE: Brim'`.
  - Time and grams: in the G-code header, "; model printing time" and "; total filament weight [g]" (tested 2026-10-24).
  - Where support lands: unzip `Metadata/plate_1.gcode` into the session scratchpad, never the repo, and print each support feature's z range (tested 2026-10-29):

    ```sh
    awk '/^; Z_HEIGHT:/{z=$3} /^; FEATURE:/{f=substr($0,12)} f ~ /[Ss]upport/ && /^G1 / && /E[0-9.]+/{if(!(f in lo))lo[f]=z; hi[f]=z} END{for(f in lo) print f": z "lo[f]"–"hi[f]}' plate_1.gcode
    ```

  - Filament share per feature: in the same pass, sum the positive E values per feature. The G-code uses relative E (`M83`).

## Reading the profiles and the manual offline

- Profiles: one JSON file per preset in `machine/`, `process/` and `filament/` under the BBL folder above; `filament/` also has vendor subfolders (`tools/bambu-profile`). The same files are on GitHub under `resources/profiles/BBL/` at tag v02.09.01.70.
- `inherits` names a parent by its `name` field, not its file name, in the same folder. The child's keys override the parent's (tested by flattening). A machine profile's `include` list adds template files, found by `name` the same way. Merge them over the parent and under the profile's own keys, leaving out each template's `name` and `instantiation` (tested). Chains:
  - `Bambu Lab X2D 0.4 nozzle` ← `fdm_bbl_3dp_002_common` ← `fdm_machine_common`, plus five `Bambu Lab X2D 0.4 nozzle template …` includes. The 0.2, 0.6 and 0.8 profiles inherit from the 0.4 one.
  - `0.24mm Standard @BBL X2D` ← `fdm_process_dual_0.24_nozzle_0.4` ← `fdm_process_dual_common` ← `fdm_process_common`.
- The presets selected in Bambu Studio are in `.presets` in `~/Library/Application Support/BambuStudio/BambuStudio.conf`. That file also holds access codes and tokens, so read only `.presets`.
- `tools/bambu-profile <machine|filament|process> "<name>"` prints a flattened profile, with `inherits` and `include` both resolved. It reads the app that `BAMBU_APP` names, by default `/Applications/BambuStudio.app`; `just slice` sets it from `bambu_app`.
- `just manual` downloads the manual once into the git-ignored `out/manual/`, converts it to text unless the text is newer than the PDF, and prints the text's path. Never commit the PDF or the text. `pdftotext` drops the ligatures, so "firmware" appears as "rmware" and "Start" as "Sta" (tested).
