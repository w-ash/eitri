# OpenSCAD toolchain

Reference for running OpenSCAD headless in eitri's build, render and check loop ([docs/backlog/v0.1.x.md](../backlog/v0.1.x.md)), as of 2026-10-23.

Read from source: [openscad/openscad master `2ec8e9c`](https://github.com/openscad/openscad/tree/2ec8e9cad48a9305317e1ee76c2f61e896a62da0) (bare `src/…` paths), [BOSL2 `d29d3e5`](https://github.com/BelfrySCAD/BOSL2/tree/d29d3e5fcfe830e7554b7c914b1431dbf23e82d8), and the Manifold commit OpenSCAD pins, [`0edd9d5`](https://github.com/elalish/manifold/tree/0edd9d54876f3135e431575214dd6d8a72866fee). Master is 12 days newer than the 2026.10.11 snapshot. "Tested 2026-10-23" marks a result run on OpenSCAD 2026.10.11 (Homebrew `openscad@snapshot`) with `--backend=manifold --hardwarnings`; every flag `tools/openscad` and the `justfile` pass works on it.

## Tested on 2026.10.11

All tested 2026-10-23.

- Summary JSON: a top level that is one primitive with no CSG prints `{"geometry":{"bounding_box":{"max","min","size"},"convex":…,"dimensions":3,"facets":…,"triangular":…}}`, with no `simple` or `vertices`. A CSG result prints `simple`, `vertices` and `facets`. Re-importing the 3MF through `difference() { import(file); cube(0); }` (`tools/mesh.scad`) always gives `simple`.
- `--hardwarnings`: an unknown variable exits 1. A failed `assert()` before any shape exits 1 ("Current top level object is empty"). After a shape, whether the assert is at top level, in a module or in a function argument, it prints `ERROR:` and `TRACE:` lines, exits 0 and writes a partial 3MF; a PNG with the assert first exits 0 with a blank image. BOSL2-style `echo("WARNING: …")` prints `ECHO: "WARNING: …"` and exits 0, and so does a `DEPRECATED:` line. A PNG export exits 0 after `import()` prints `WARNING: Could not read file`; a 3MF export of the same exits 1 with an empty top level.
- Output paths: a read-only folder prints `Can't open file "…" for export`, with no group prefix, and exits 0. A missing folder prints `'…' is not a directory for output file … - Skipping` and exits 1.
- Streams: in a 3MF or PNG export, ERROR, TRACE, WARNING, DEPRECATED and ECHO lines go to stderr and stdout stays empty. With `--export-format=echo -o -` they go to stdout. An EXPORT-ERROR line: not triggered.
- Parameter sets: a missing set builds with defaults, silently, exit 0. A missing file prints `ERROR: Cannot open Parameter Set '…' for reading` and exits 0. An unknown key is dropped silently. A value outside the Customizer `[min:step:max]` is clamped silently, even under `--hardwarnings` (500 in `[1:1:100]` gives 100); an off-step value is kept (57.3). `-D` is not clamped, and when `-D` and the set give the same parameter, the set wins. A vector as a JSON array is ignored; as a string, `"[3, 4]"`, it applies. A dropdown value not in its list is ignored silently, even under `--hardwarnings`: with `shape = "a"; // [a, b, c]`, a set value `"z"` builds with `"a"`, exit 0, while `"b"` applies; the same holds for a number list (`// [1, 2, 3]` given 9) and a labeled list (`// [x:Ex, y:Why]` given `"z"`).
- Cost: two `-o` in one call evaluate the script once per output (43.8 s against 22.4 s on a heavy BOSL2 part). A view rendered from the exported 3MF took 2.6 s, against 22.9 s from source.
- `color()` reaches renders drawn from the 3MF: a black cube renders as a black silhouette.
- Open meshes: a bare open `polyhedron` exports with exit 0 and `convex: false`. Unioned with another shape, it fails with `WARNING: PolySet -> Manifold conversion failed: NotManifold` and exits 1. `just check` re-imports through `tools/mesh.scad`, so it fails an open mesh the same way.

## Version and backend

- 2021.01 is still the latest release ([releases](https://github.com/openscad/openscad/releases)). Homebrew disabled the `openscad` cask on 2026-09-01; `openscad@snapshot` is 2026.10.11 and links `openscad` into /opt/homebrew/bin (`brew info`).
- Manifold has been the default backend since [PR #5833](https://github.com/openscad/openscad/pull/5833), merged 2025-08-17: "'Manifold' (new/fast) [default]" (`src/openscad.cc:888-889`). `--backend` ignores case and exits 1 on an unknown name (`src/glview/RenderSettings.cc:16-26`, `src/openscad.cc:1025-1033`).
- `--render` evaluates full geometry for a PNG. `--render=force` also converts the top-level result to Manifold geometry (`src/openscad.cc:1035-1045, 495-509`, `src/geometry/GeometryUtils.cc:529-545`). Without it, a top level that is a plain mesh reports `convex`, `triangular`, `facets` and the bounding box, but no `simple` or `vertices` (`src/RenderStatistic.cc:357-371`; tested 2026-10-23). Write the value with `=`, since the option takes an implicit value (`src/openscad.cc:891-892`; inference).

## Exit codes and messages

- Every message goes to stderr as `GROUP: text in file F, line N`. The groups are ERROR, WARNING, TRACE, DEPRECATED, EXPORT-ERROR, EXPORT-WARNING, UI-WARNING, FONT-WARNING and ECHO (`src/utils/printutils.cc:118-121, 180-198`, `src/utils/printutils.h:91-98`). `-q` prints errors only and hides warnings (`printutils.cc:118`). An `echo` export evaluates no geometry (`src/openscad.cc:473-474`) and sends every message, warnings included, to the echo output instead of stderr (`src/openscad.cc:133-150, 579-582`).
- `--hardwarnings` throws on the WARNING group only (`src/utils/printutils.cc:126-129`), and the CLI then exits 1 (`src/openscad.cc:1186-1187`). A warning while parsing, such as "Can't open include file" (`src/core/lexer.l:457`), aborts the parse (`src/core/parser.y:826-827`). It lets ERROR, DEPRECATED, EXPORT-*, UI-WARNING, FONT-WARNING and ECHO through. Exception: a PNG export exits 0 after an `import()` WARNING (tested 2026-10-23).
- A failed `assert()` logs ERROR and throws (`src/core/Expression.cc:682-684`). The file-level catch swallows it (`src/core/SourceFile.cc:192-197`) and keeps the top-level objects already built (`src/core/LocalScope.cc:82-92`). So: if nothing is built yet, a 3MF export fails with "Current top level object is empty" and exits 1 (`src/openscad.cc:202-212, 516-518`); after a top-level object, a partial 3MF exits 0, wherever the assert sits; a PNG skips the empty check (`dim` is 0, `src/openscad.cc:513-516`) and exits 0 with a blank image (all tested 2026-10-23). An issue about assert exit codes: not found.
- BOSL2 warns with `echo()`, so its warnings print as `ECHO: "WARNING: …"` and pass `--hardwarnings` (BOSL2 `joiners.scad:1265`, `skin.scad:2458`, `shapes2d.scad:2936`; `deprecate()` at `utility.scad:910-913`). BOSL2's own tests pass only on exit 0 with no output (BOSL2 `CLAUDE.md:25`).
- An `include` that reassigns a main-file variable warns, which is fatal with `--hardwarnings`. A main-file assignment over an included variable is silent, and so is `-D` (`src/core/parser.y:768-782`).
- If the output file can't be opened, the export's result is ignored and OpenSCAD exits 0 (`src/openscad.cc:214-218`, `src/io/export.cc:238-250`); a missing output folder exits 1 instead (tested 2026-10-23). The summary file is written only after a successful export (`src/openscad.cc:516-538`), so the old one survives a failed build unless deleted.
- `--check-parameter-ranges=true` (off by default, `src/utils/printutils.cc:29`) adds warnings for `cube()` and `sphere()` sizes of zero or less and for zero `scale()` (`src/core/primitives.cc:154-158, 426-428`, `src/core/TransformNode.cc:70-75`).

## Summary JSON

`--summary geometry --summary bounding-box --summary-file -` (or `--summary all`) prints one object per `-o` on stdout. For a CSG result or a mesh re-imported through `tools/mesh.scad` (a lone primitive differs; tested 2026-10-23):

```json
{"geometry": {"dimensions": 3, "simple": true, "vertices": 0, "facets": 0,
  "bounding_box": {"min": [0, 0, 0], "max": [0, 0, 0], "size": [0, 0, 0]}}}
```

- From `src/RenderStatistic.cc:147-159, 393-406`. `bounding_box` only appears inside `geometry`, so `--summary bounding-box` alone prints none. `camera`, `time` and `cache` are separate top-level keys (`409-451`). Empty geometry and a geometry list (lazy union) print no `geometry` key (`217-219, 339-341`). A CGAL top level adds `edges` and `volumes` (`374-389`). There's no volume or area for 3D; `area` is 2D only (`241-244`).
- `simple` is Manifold's status check (`src/geometry/manifold/ManifoldGeometry.cc:81-84`), and Manifold promises "guaranteed manifold output" (Manifold `README.md:10`). So it's almost always true and says nothing about floating pieces or thin walls (inference). In tests it was always true; an open mesh failed the conversion with exit 1 instead of reporting false (tested 2026-10-23).
- Without `--summary-file`, the stderr log for a Manifold result also prints `Genus:` (`src/RenderStatistic.cc:293-303`).

## Floating or disconnected pieces

- The Manifold summary has no body count; only CGAL reports one (`src/RenderStatistic.cc:383`).
- Euler count, with OpenSCAD and jq only: Manifold's `Genus()` is `1 - (V - E + F)/2` and is "only meaningful for a single mesh" (Manifold `src/manifold.cpp:410-417`). On a closed triangle mesh E = 3F/2, so `vertices/2 - facets/4` gives shells minus handles (arithmetic). One solid with N through-openings gives 1 − N; each floating piece or sealed void adds 1, and each extra through-hole subtracts 1 (inference). It needs an expected value for each part, and a floating piece plus an extra hole cancel out.
- CGAL: `--backend=cgal --render=force` reports `volumes` (`src/RenderStatistic.cc:374-389`), which also counts the outer space (inference from CGAL's Nef model). The help text calls CGAL "old/slow" (`src/openscad.cc:888-889`).
- Exact count: union-find over the faces of an OFF export, which writes shared vertex indices (`src/io/export_off.cc:47-66`). openscad-agentic-workspace does this in TypeScript (`libs/geometry/src/check/bodies.ts:6-24`). With OpenSCAD and jq alone it needs awk or the planned Python step (inference).

## Render flags

- With no `--camera`, view-all and autocenter are on (`src/openscad.cc:345-348`): rotation [55, 0, 25], distance 140, FOV 22.5°, 512 × 512, perspective (`src/glview/Camera.cc:14-17, 90-96`, `Camera.h:29`). A `$vpr`, `$vpt`, `$vpd` or `$vpf` in the file then overrides the view (`Camera.cc:103-155`).
- `--camera` with 7 numbers is translate x,y,z, rotate x,y,z (as `$vpr`), distance; with 6 it's eye x,y,z, center x,y,z, with no roll (`Camera.cc:33-53`). Any other count exits 1, while a non-number only logs (`src/openscad.cc:328-344`). Either form locks the camera: the file's `$vp*` are ignored, and view-all and autocenter stay off unless passed (`Camera.cc:52, 105`, `src/openscad.cc:345-356`).
- `--viewall` sets the distance so a sphere around the bounding box fits (`Camera.cc:57-74`), and `--autocenter` aims at the box center. In ortho the half-height is distance × tan(FOV/2) (`src/glview/GLView.cc:198-200`), so with view-all the visible height is about the box diagonal, whatever the `--imgsize` (arithmetic).
- Rotations: [0, 0, 0] top, [90, 0, 0] front (looking +y), [90, 0, 90] right (looking −x), [180, 0, 0] bottom (derived from `Camera.cc:178-181` and `GLView.cc:206-214`; openscad-agentic-workspace uses the same set, `libs/core/src/views/views.ts:13-20`).
- `--projection` takes o, ortho, orthogonal, p or perspective, and exits 1 on anything else (`src/openscad.cc:358-368`); `--imgsize=W,H` sets the size (`370-386`). `--view` takes axes, scales, edges and crosshairs (`src/io/export.h:338-343`), and logs and ignores an unknown one (`src/openscad.cc:1050-1059`). `edges` draws the triangle edges in a render (`src/glview/PolySetRenderer.cc:236-241`).
- `--colorscheme` takes Cornfield (built-in default, `src/glview/ColorMap.cc:19`), BeforeDawn, ClearSky, Daylight Gem, DeepOcean, Metallic, Monotone, Nature, Nocturnal Gem, Nord Dark, Nord Light, Solarized, Starnight, Sunset, Tomorrow or Tomorrow Night (`color-schemes/render/*.json`). An unknown name prints the list and exits 1 (`src/openscad.cc:734-749`). A render draws the model's `color()` colors (`PolySetRenderer.cc:130-136`), also when drawn from the 3MF (tested 2026-10-23).
- Each invocation has one camera (`src/openscad.cc:1132`) and reparses the file for every `-o` (`1162-1184`), so each view is a separate run with its own evaluation (tested 2026-10-23: two outputs took twice as long as one). openscad-agentic-workspace renders its views from the exported 3MF through an `import()` wrapper (`libs/core/src/views/views.ts:68-77, 106-121`); eitri's `render` does the same through `tools/mesh.scad`. Input `-` reads the script from stdin (`src/openscad.cc:1163, 586`), so a wrapper needs no file (inference).
- For a flat-backed part with a curved front and a raised center (inference): an iso view, and a top view tilted toward the camera, show the layout and the seats' tilt by shading. Ortho front and right views show the flat base line, the dish rise and the center's height, and a bottom view confirms the flat back. With view-all, the backlog's proposed 240 × 222 mm gives a visible height of about 333 mm, so the story's 12 mm dish rise is about 28 px of 768 (arithmetic). With `--autocenter`, no view-all and distance d, an ortho view spans 0.398·d·W/H by 0.398·d mm, so d = L / (0.36·W/H) fills 90% of the width with a part of length L (arithmetic).

## Parameter sets

- File format: `{"fileFormatVersion": "1", "parameterSets": {"<set>": {"<parameter>": "<value>"}}}`. OpenSCAD writes values as strings and never checks the version on read (`src/core/customizer/ParameterSet.cc:11-13, 15-48, 50-63`). A vector value must be a string such as `"[1, 2]"` (`src/core/customizer/ParameterObject.cc:160-167`); a JSON array is ignored (tested 2026-10-23).
- A parameter is a top-level assignment of a literal number, string, bool or vector of up to 4 numbers, outside `/* [Hidden] */` (`ParameterObject.cc:455-546`). A set key that names anything else is ignored without a message (`574-584`).
- Silent cases, by the source: `-p` without `-P`, or the reverse, applies nothing (`src/openscad.cc:628`). A missing or invalid file logs ERROR and builds with defaults (`ParameterSet.cc:19-29`; the result is ignored at `src/openscad.cc:631`). An unknown set name builds with defaults and no message (`src/openscad.cc:635-641`). Numbers are clamped to the Customizer `[min:step:max]` range (`ParameterObject.cc:116-132`). A dropdown value not in its list keeps the default (tested 2026-10-23). A parameter the set leaves out keeps its default (`574-584`). Tested 2026-10-23, except `-p` without `-P` and an invalid file; the clamp also holds under `--hardwarnings`.
- `-D var=val` is appended after the file (`src/openscad.cc:614, 1078-1083`) and replaces a top-level assignment of the same name in place, without a warning or a clamp (`src/core/parser.y:768-769, 783-785`; tested 2026-10-23), so it can set derived values too. The set applies after parsing, so when both set one parameter, the set wins (`src/openscad.cc:614-641`; tested 2026-10-23).
- `-o <file>.param` writes the parameters as JSON (`name`, `caption`, `group`, `type`, `initial`, `min`, `max`, `step`) without evaluating geometry (`src/io/export_param.cc:38-66`, `ParameterObject.cc:141-153`, `src/openscad.cc:460-462`).

## 3MF export options

- `-O export-3mf/<key>=<value>`, listed by `--help-export` (`src/openscad.cc:866-868, 716-730`). The keys are `color-mode` (model, none or selected-only), `unit` (default millimeter), `color`, `material-type` (color, or basematerial by default), `decimal-precision` (1–16, default 6), `add-meta-data` (default true), and `meta-data-title`, `-designer`, `-description`, `-copyright`, `-license-terms` and `-rating` (`src/core/Settings.cc:430-484`).
- The CLI starts from these defaults, not from saved GUI preferences (`src/io/export.h:77-90`). An unknown key is ignored (inference from the same lines).
- Colors are kept by default (`src/core/Settings.cc:432-439`). Each item in a geometry list becomes its own object (`src/io/export_3mf_v2.cc:262-268`), but top-level parts only stay separate with experimental `--enable=lazy-union` (`src/Feature.cc:31`). Bambu Studio's "load geometry data only" warning is harmless ([Bambu forum](https://forum.bambulab.com/t/the-3mf-is-not-from-bambu-lab-load-geometry-data-only/2352)). Bambu Studio 02.08.02.61 words it "The 3mf file has invalid config, load geometry data only" (tested 2026-10-23, opening `just build` output); the 3MF carries no Bambu print settings, so the slicer uses its own (inference).

## BOSL2

- Weekly release tags, the latest v2.0.777 at `9af06e7` (`git ls-remote`, [BOSL2](https://github.com/BelfrySCAD/BOSL2)). The README says "BOSL2 IS BETA CODE" (`README.md:10`), and its install steps download master, not a tag (`README.md:37`).
- Load it with `include <BOSL2/std.scad>` (BOSL2 `std.scad:1-5`), which asserts OpenSCAD 2021.01 or later (`std.scad:8`). Gears, screws, threading and hinges need their own includes (BOSL2 `CLAUDE.md:55`). `use` "imports modules and functions", and "A cannot see B's global variables" ([manual](https://en.wikibooks.org/wiki/OpenSCAD_User_Manual/Include_Statement)).
- `OPENSCADPATH` is searched after the including file's folder and before the built-in library folders (`src/core/parsersettings.cc:86-107, 147-160`). Conflict: the manual lists the installation's folder first. A relative entry resolves against the current directory (`parsersettings.cc:159`). A missing library is a WARNING (`src/core/lexer.l:457`), so it's fatal only with `--hardwarnings`.

## Recommendations for eitri

1. **Fail on what `--hardwarnings` misses.** Done: every recipe runs OpenSCAD through `tools/openscad`, without `--hardwarnings` since 2026-11-05 (it throws on the geometry cache's harmless "Node didn't fit into cache" warning on large plates), and the wrapper fails on a line starting `ERROR:`, `TRACE:`, `WARNING:`, `DEPRECATED:`, `EXPORT-ERROR:` or `ECHO: "WARNING` on either stream, except that cache warning, and passes no `-q`. It catches an assert after a shape (partial 3MF, exit 0), BOSL2's echoed warnings, and a PNG drawn after a failed `import()` (Tested on 2026.10.11). It doesn't match the unprefixed `Can't open file`, so `build` also fails with `FAIL: OpenSCAD wrote no …` when the 3MF is missing or empty after OpenSCAD exits 0 (`justfile`; tested 2026-10-23 with a read-only out folder).
2. **Lint each parameter set against `-o <name>.param`.** Deferred until parts use parameter sets. The lint would fail when a set key isn't a parameter, a number falls outside its `min` and `max`, or a parameter has no `caption`, since OpenSCAD drops unknown keys and clamps out-of-range numbers without a message, even under `--hardwarnings` (Parameter sets). For now, `build` fails only on a missing set name (`justfile`).
3. **Check topology by number.** Not adopted: renders cover floating pieces (`.claude/skills/design-model/SKILL.md`). The method is under Floating or disconnected pieces.
4. **Frame the profile views by distance, not view-all.** Not adopted: views stay fitted with `--viewall`, and a detail too small to judge is cropped and enlarged with `sips` (`.claude/skills/design-model/SKILL.md`).
5. **Set `OPENSCADPATH` to an absolute path wherever OpenSCAD runs.** The `justfile` exports it; the deferred `PostToolUse` hook runs outside `just` and needs it too. Without the path, the BOSL2 include fails and `--hardwarnings` rejects every edit (BOSL2). `--export-format=echo -o -` compiles without geometry and prints every message on stdout, so the hook needs no temporary file (Exit codes and messages; tested 2026-10-23).
6. **Leave color out of the 3MF.** Done: `build` passes `-O export-3mf/color-mode=none` (`justfile`). Without it, a render drawn from the 3MF keeps `color()` colors, so a black part renders as a flat silhouette, hiding the tilts the views exist to show (tested 2026-10-23).
