# Claude Code skills for eitri

Reference for writing and placing Claude Code skills for eitri's build, render and check loop, as of 2026-10-29. Pages cited below were fetched that day; none states a revision date unless noted.

## Skill anatomy

- Project skills live at `.claude/skills/<name>/SKILL.md`; commit them to share. Personal skills live in `~/.claude/skills/`. A skill in a subdirectory loads when Claude first works on files there ([skills](https://code.claude.com/docs/en/skills#choose-where-skills-load)).
- Spec: `name` is 1-64 lowercase letters, digits and hyphens, with no leading, trailing or doubled hyphen, and must match the directory name. `description` is 1-1024 characters ([spec](https://agentskills.io/specification)). Anthropic's platform also bars XML tags and the words `anthropic` and `claude` in `name` ([best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#skill-structure)).
- Claude Code adds `when_to_use`, `argument-hint`, `arguments`, `paths`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks` and `shell`. It ignores unknown fields without an error, and reads frontmatter only when the opening `---` is line 1 ([skills](https://code.claude.com/docs/en/skills#frontmatter-reference)).
- Malformed YAML loads the body with no fields, so `/name` works but Claude can't match the description. `claude plugin validate .claude/skills` finds the error (v2.1.233 or later) ([skills](https://code.claude.com/docs/en/skills#skill-not-triggering)).
- `disable-model-invocation: true` keeps the skill out of Claude's context until invoked by hand. Use it for side-effect workflows ([skills](https://code.claude.com/docs/en/skills#frontmatter-reference)).
- `paths` limits automatic activation to files under the working directory that match ([skills](https://code.claude.com/docs/en/skills#frontmatter-reference)).
- `allowed-tools` pre-approves tools only for the invoking turn; the grant clears on the next message. `model` and `effort` also apply only for the rest of the current turn ([skills](https://code.claude.com/docs/en/skills#frontmatter-reference)).
- `context: fork` runs the skill in a subagent that does not see the conversation ([skills](https://code.claude.com/docs/en/skills#run-skills-in-a-subagent)).
- `` !`cmd` `` runs before Claude sees the skill. A failed command aborts the whole invocation ([skills](https://code.claude.com/docs/en/skills#inject-dynamic-context)).
- Once invoked, `SKILL.md` stays in context across turns and is not re-read, "so every line is a recurring token cost". After compaction, each skill keeps its first 5,000 tokens, within a 25,000-token combined budget filled from the most recent skill ([skills](https://code.claude.com/docs/en/skills#skill-content-lifecycle)).
- Size: keep `SKILL.md` under 500 lines ([skills](https://code.claude.com/docs/en/skills#add-supporting-files)) and under 5,000 tokens; the name and description cost about 100 tokens ([spec](https://agentskills.io/specification#progressive-disclosure)).
- Supporting files load only when read. Link each from `SKILL.md` one level deep, give any file over 100 lines a table of contents ([best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#avoid-deeply-nested-references)), and say when to read it: "Read `references/api-errors.md` if the API returns a non-200 status code" beats "see references/ for details" ([Agent Skills best practices](https://agentskills.io/skill-creation/best-practices#structure-large-skills-with-progressive-disclosure)).
- Scripts are run, not loaded. Say in the text whether Claude should run a script or read it ([best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#provide-utility-scripts)).
- Portability: claude.ai uploads and the Skills API accept only `name`, `description`, `license`, `compatibility`, `metadata` and `allowed-tools`. Other keys fail on upload ([skills](https://code.claude.com/docs/en/skills#using-skill-frontmatter-outside-claude-code)).

## Descriptions that trigger

- At startup Claude sees only each skill's `name` and `description`, so "the description carries the entire burden of triggering" ([Agent Skills: descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)).
- State what the skill does and when to use it, with the terms a request would use. Write in the third person ("Processes Excel files"), not "I can help" or "You can use this", since the description goes into the system prompt ([best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#writing-effective-descriptions)). Agent Skills adds: phrase the trigger as an instruction ("Use this skill when..."), describe the user's intent rather than the mechanics, list cases where the user doesn't name the domain, and keep it to a few sentences ([Agent Skills: descriptions](https://agentskills.io/skill-creation/optimizing-descriptions#writing-effective-descriptions)). "Does X. Use when Y." satisfies both (inference).
- Agents "typically only consult skills for tasks that require knowledge or capabilities beyond what they can handle alone", so a simple one-step request may not trigger a matching skill ([Agent Skills: descriptions](https://agentskills.io/skill-creation/optimizing-descriptions#how-skill-triggering-works)).
- Put the key use case first. Description plus `when_to_use` is cut at 1,536 characters (`skillListingMaxDescChars`). The whole listing has a budget of 1% of the context window (`skillListingBudgetFraction`); past it, descriptions of the least-invoked skills drop first ([skills](https://code.claude.com/docs/en/skills#skill-descriptions-are-cut-short)).
- Triggers too often: make the description more specific, or set `disable-model-invocation: true` ([skills](https://code.claude.com/docs/en/skills#skill-triggers-too-often)). Too broad: say what the skill does not do, or where it ends and a nearby capability starts ([Agent Skills: descriptions](https://agentskills.io/skill-creation/optimizing-descriptions#the-optimization-loop)).

## Writing the body

- "Keep the body itself concise... State what to do rather than narrating how or why," with the same test as CLAUDE.md: only what Claude can't find on its own ([skills](https://code.claude.com/docs/en/skills#types-of-skill-content); [Claude Code best practices](https://code.claude.com/docs/en/best-practices#put-team-procedures-in-skills)). For each line: "Would the agent get this wrong without this instruction?" If not, cut it ([Agent Skills best practices](https://agentskills.io/skill-creation/best-practices#add-what-the-agent-lacks-omit-what-it-knows)).
- Write guidance as standing instructions for the whole task ("Run the tests after every edit") and put the most important lines first, since compaction keeps only the start ([skills](https://code.claude.com/docs/en/skills#claude-stops-following-a-skill)).
- Gotchas, concrete corrections to mistakes the agent will otherwise make, are often the highest-value content. Keep them in `SKILL.md`, where the agent reads them before the situation, and add each correction you have to make ([Agent Skills best practices](https://agentskills.io/skill-creation/best-practices#gotchas-sections)).
- "Overly comprehensive skills can hurt more than they help": the agent follows instructions that don't apply. Prefer concise steps with a working example ([Agent Skills best practices](https://agentskills.io/skill-creation/best-practices#aim-for-moderate-detail)).
- Give one default with an escape hatch, not a menu of options; use one term per concept throughout; keep dated facts out or in an "old patterns" section ([best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#anti-patterns-to-avoid); [#use-consistent-terminology](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#use-consistent-terminology)).
- Match specificity to fragility: explain why where the agent must judge, and give exact commands where one sequence is safe ([Agent Skills best practices](https://agentskills.io/skill-creation/best-practices#match-specificity-to-fragility)). A template or checklist beats prose for output formats and multi-step workflows ([Agent Skills best practices](https://agentskills.io/skill-creation/best-practices#templates-for-output-format)).
- A rule that must hold every time goes in a hook, which can live in the skill's `hooks` frontmatter and runs from invocation until the session ends ([skills](https://code.claude.com/docs/en/skills#claude-stops-following-a-skill)).

## Testing a skill

- Build evaluations from failures you have seen, then compare runs with and without the skill in fresh sessions; "leftover context from authoring the skill will mask gaps". Turn a project skill off for the baseline with `"off"` in `skillOverrides` ([skills](https://code.claude.com/docs/en/skills#evaluate-and-iterate-on-a-skill); [best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#build-evaluations-first)).
- Trigger tests: about 20 queries, half should-trigger and half near-miss should-not-trigger, each run 3 times, passing at a trigger rate above 0.5. Hold out about 40% as a validation set, and don't paste keywords from failed queries into the description ([Agent Skills: descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)).
- The `skill-creator` plugin automates the with/without comparison, blind A/B of two versions, and description tuning ([skills](https://code.claude.com/docs/en/skills#run-evals-with-skill-creator)).
- Test with each model you will use. Haiku may need more guidance than Opus ([best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices#test-with-all-models-you-plan-to-use)).
- `/skill-doctor` (v2.1.252 or later) reports each skill's context cost and use count and flags skills never invoked. It is not a linter ([skills](https://code.claude.com/docs/en/skills#find-unused-skills)). To confirm a skill is listed, ask "What skills are available?" ([skills](https://code.claude.com/docs/en/skills#skill-not-triggering)).
- `claude plugin eval` runs eval cases in fresh sessions with a no-plugin baseline and is meant for plugin skills; it requires Claude Code v2.1.269 or later ([plugin evals](https://code.claude.com/docs/en/plugin-evals.md)). A skill folder can be tested as its own plugin with `plugins: ["../.."]` (source: embedded eval reference, no URL, 2026-10-23).
- `skills-ref validate ./<skill>` checks frontmatter against the spec ([spec](https://agentskills.io/specification)).
- Not found: a published benchmark comparing skill triggering rates across descriptions.

## What belongs where

- **CLAUDE.md:** loaded every session; "every line in it takes a little of Claude's attention on *every* task". Target under 200 lines. Write a line only if Claude couldn't find it in the repo or wouldn't go and look ([memory](https://code.claude.com/docs/en/memory#write-effective-instructions); [Claude Code best practices](https://code.claude.com/docs/en/best-practices#keep-claude-md-short)).
- **`.claude/rules/`:** a rule without `paths` loads at launch like `.claude/CLAUDE.md`. A rule with `paths` loads when Claude reads, writes or edits a matching file, `cat` and `head` included, and drops after compaction until a match recurs. `paths` is the only frontmatter field read; if the YAML doesn't parse, the rule loads as if it had no `paths`. One topic per file ([memory](https://code.claude.com/docs/en/memory#path-specific-rules); [context window](https://code.claude.com/docs/en/context-window#what-survives-compaction)).
- **Skills:** procedures and team knowledge, loaded when relevant; "a long release procedure sitting in a skill doesn't weigh on your unrelated bug fix the way it would in `CLAUDE.md`" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices#put-team-procedures-in-skills)).
- **Hooks:** deterministic. CLAUDE.md is advisory; a PreToolUse hook blocks an action regardless ([memory](https://code.claude.com/docs/en/memory#claude-md-vs-auto-memory)). "If you keep adding emphasis to a `CLAUDE.md` line and Claude still misses it, that's a sign the line belongs in a hook", and hooks for mere preferences should go ([Claude Code best practices](https://code.claude.com/docs/en/best-practices#deterministic-and-non-deterministic-instructions)). A `PostToolUse` hook with matcher `Edit|Write` runs after file edits only. Exit 2 blocks where the event allows it; stderr goes to Claude as feedback on events that support it ([hooks guide](https://code.claude.com/docs/en/hooks-guide.md)).
- **Subagents (`.claude/agents/`):** isolated context, tool limits, and summaries for verbose work. A subagent's `skills` field preloads full skill content ([sub-agents](https://code.claude.com/docs/en/sub-agents#what-loads-at-startup)).
- **Slash commands:** `.claude/commands/` still works, but skills are preferred because they support supporting files ([skills](https://code.claude.com/docs/en/skills#choose-where-skills-load)).
- **Verification:** give Claude a check that returns pass or fail, and ask for the command and its output as evidence. A Stop hook can block the turn until the check passes, up to eight blocks in a row ([Claude Code best practices](https://code.claude.com/docs/en/best-practices#give-claude-a-check-to-run)).

## Visual feedback loops for CAD

Checked 2026-10-23; not re-checked.

- **andreahaku/openscad_claude_skill (OpenSCAD):** a 762-line `SKILL.md`, seven scripts, and a `preview` command that renders four views (iso, front, right, top). Its README does not state whether validators exit non-zero on failure ([repo](https://github.com/andreahaku/openscad_claude_skill)).
- **flowful-ai/cad-skill (CadQuery):** a wrapper runs the script, captures errors, and emits JSON so Claude can correct itself. Six-view previews; `--strict` fails on non-watertight meshes. Needs Python 3.10-3.12 because CadQuery has no wheels for 3.13 ([repo](https://github.com/flowful-ai/cad-skill)).
- **build123d-mcp:** an MCP server with rendering and dimension queries. Its self-reported CADGenBench score is 0.457, against 0.360 for blind scripts. Not verified ([PyPI](https://pypi.org/project/build123d-mcp/0.3.68/)).
- **agentcad:** an MCP server and CLI that checks watertight geometry and renders several angles. Self-described; not verified ([listing](https://hunted.space/product/agentcad)).
- Not found: independent results showing render-and-look beating numeric checks, or public failure reports beyond the limits above.
- (inference) The common shape is a deterministic wrapper that returns JSON errors and fixed-angle PNGs, with the model reading the images. That matches eitri's split between `just check` numbers and `just render` images.

## Recommendations for eitri

On 2026-10-29, `CLAUDE.md` is 67 lines, `.claude/rules/openscad.md` 60 lines (4,350 characters, path-scoped to `**/*.scad`), and `.claude/skills/design-model/SKILL.md` 128 lines (8,362 characters, about 2,100 tokens at four characters a token; inference) (`wc`).

- Keep `.claude/rules/openscad.md` path-scoped; it is far under the 40,000-character limit for on-demand files ([memory](https://code.claude.com/docs/en/memory#claude-ignores-the-end-of-my-subdirectory-claude-md)).
- Keep the rules and the never-do lines in CLAUDE.md and the build, check, render, read, fix and hand-over steps in the skill. A path-scoped rule or an uninvoked skill may be absent when it matters (see "Keep 'never do X' rules in the root file" in `claude-prompting.md`).
- Keep one skill, `design-model`, with no `paths`. A skill with `paths` loads automatically "only when working with files matching the patterns" ([skills](https://code.claude.com/docs/en/skills#frontmatter-reference)), so it wouldn't load for a model that has no file yet. Its description names the requests (design, model, make, change, resize, fix or print a model) and editing a `.scad` file under `projects/`. The body is within the 500-line and 5,000-token guidance; move a section to a linked file only if it is needed on some runs and not others.
- Put the `Bash(just *)` allow in `.claude/settings.json`, not in the skill's `allowed-tools`, since skill grants clear after one message.
- Keep the planned `PostToolUse` hook on `Edit|Write`, limited to a fast `--hardwarnings` compile of `.scad` files. Leave renders out of hooks, since reading them is a judgment step.
- Add no subagent or slash command for now.
- Test: run two fresh sessions on one model prompt, with the skill on and with it `"off"` in `skillOverrides`. Check that every render was read and that the hand-over names the 3MF, orientation and print checks. Confirm the skill is listed with "What skills are available?" and check its cost with `/skill-doctor`.
- The backlog build story says two published skills have validators that exit 0 on a broken file. The andreahaku README does not say that. Verify before relying on it.
