# v0.1.x: toolchain

The OpenSCAD toolchain: build, render and check recipes, the `design-model` skill and the project
settings. What the user makes with it lives in `projects/`, one folder per project, with its brief and
models ([project-format.md](../reference/project-format.md)).

#### Toolchain

- [ ] **Install and pin the toolchain**
    - Effort: S
    - What: OpenSCAD's development snapshot, BOSL2, a uv project with the dev tools, a `justfile`, and Bambu Studio on the user's Mac.
    - Why: every part depends on one known OpenSCAD and BOSL2.
    - Dependencies: None
    - Status: In Progress
    - Notes:
        - Done 2026-10-23: OpenSCAD 2026.10.11, Bambu Studio 02.08.02.61, BOSL2, and `.claude/settings.json` with the allows, the BOSL2 `CLAUDE.md` exclude and the compile hook. After the first model: the uv project and a justfile check of `openscad --version`, since `brew upgrade` moves the snapshot cask ([openscad-toolchain.md](../reference/openscad-toolchain.md)).
        - OpenSCAD: `brew install --cask openscad@snapshot` (2026.10.11 on 2026-10-23). The `openscad` cask (2021.01) is disabled for failing Gatekeeper (`brew info`, 2026-10-23).
        - BOSL2 (https://github.com/BelfrySCAD/BOSL2): a git submodule at `lib/BOSL2` on tag `v2.0.777`, with the recipes setting `OPENSCADPATH` to `lib/`. A Bambu forum user reports that MakerWorld's Parametric Model Maker supports BOSL2 (unofficial).
        - uv project: a `pyproject.toml` with the dev tools and `justfile` gates for them. Python 3.14.
        - Bambu Studio: `brew install --cask bambu-studio`.
        - `.claude/settings.json`: allows `Bash(just *)`, `Bash(openscad *)` and `Bash(sips *)`, not `Bash(uv run *)`, which approves anything after it. `claudeMdExcludes` skips `lib/BOSL2/CLAUDE.md`, which is for BOSL2's own contributors (Claude Code memory docs: https://code.claude.com/docs/en/memory). A `PostToolUse` hook on `Edit|Write` runs `.claude/hooks/scad-compile.sh`: an echo-export compile through `tools/openscad` of each edited `.scad` file outside `lib/`, which exits 2 with the error lines so Claude sees them (Claude Code hooks reference: https://code.claude.com/docs/en/hooks). Ruff on `.py` files waits for Python.

- [ ] **Build, render and check recipes**
    - Effort: M
    - What: `just build <name> [set]` exports `out/<name>/<name>.3mf`, `just render <name>` writes preview PNGs, and `just check <name>` tests the mesh.
    - Why: Claude checks each part by its numbers and its renders before the user prints it.
    - Dependencies: Install and pin the toolchain
    - Status: In Progress
    - Notes:
        - Done 2026-10-23, with OpenSCAD and jq only: the `justfile`, `tools/openscad` (fails on any OpenSCAD error or warning, BOSL2's echoed warnings included) and `tools/mesh.scad` (render and check read the built 3MF). `check` tests manifold, min z = 0 and bed fit from OpenSCAD's summary JSON. After the first model: the pytest check with a body count, and a parameter-set lint, since OpenSCAD drops unknown keys and clamps values to the Customizer range without a message ([openscad-toolchain.md](../reference/openscad-toolchain.md)).
        - Done 2026-10-24: `just slice` (the justfile's presets, per-model `.slice.json` overrides, verified), `tools/bambu-profile`, `just manual`, a bottom render, auxiliary-hotend notes in `check`, and `check-all` in a temporary folder so it never touches `out/` ([bambu-x2d.md](../reference/bambu-x2d.md)).
        - Done 2026-10-24: `design-model` has the user weigh the print trade-offs (layer height, walls and infill, orientation, pieces, fit tests) with the first questions on a model.
        - Done 2026-10-29: `just slice` writes the `.slice.json` keys into the process profile's `different_settings_to_system[0]`, so Bambu Studio keeps them when it opens the `-print.3mf` (commit d930a87). Before, a sliced 3MF opened with support disabled. Confirmed in the app on 2026-10-29 that the settings came through ([bambu-x2d.md](../reference/bambu-x2d.md)).
        - Done 2026-11-04: every Bambu Studio 02.08.02.61 CLI option is listed in [bambu-studio-cli.md](../reference/bambu-studio-cli.md), from `--help` (57 options) and Bambu's wiki (16). A `.slice.json` `"cli"` list passes any option `just slice` doesn't set itself, checked against `--help`. `just slice` also writes `<stem>-settings.json` (`--export-settings`) and `<stem>-plate.png` (`--export-png`, in a second run, since that option must run alone).
        - Layout: `projects/<project>/<model>.scad`, with an optional `<model>.json` parameter-set file beside it for named variants (`openscad -p <file> -P <set>`).
        - Use the Manifold backend; confirm the flag and `--hardwarnings` in the snapshot's `openscad --help`.
        - Render: fixed iso, front, top, side and bottom views with `--camera`, `--imgsize` and `--colorscheme`, so renders of one part compare across builds.
        - Check (pytest over the exported mesh): one closed solid, or the body count the part declares; the bounding box matches the part's dimensions; it fits the build volume. A mesh library such as trimesh is a candidate; confirm that it reads 3MF.
        - Fail loudly: compile with `--hardwarnings` and exit non-zero on any warning, and print the bounding box as JSON before rendering, so arithmetic doesn't cost an image read. Two published OpenSCAD skills have validators that exit 0 on a broken file (https://github.com/iancanderson/openscad-agent, https://github.com/andreahaku/openscad_claude_skill).
        - A project skill, `.claude/skills/design-model/SKILL.md`, gives the loop from the user's request to the hand-over: when to run each recipe and what to look for in each view. The recipes do the work; the skill stays short ([claude-code-skills.md](../reference/claude-code-skills.md), [claude-prompting.md](../reference/claude-prompting.md)).
        - X2D build volume: 256 × 256 × 260 mm with the main nozzle, 235.5 × 256 × 256 mm with the auxiliary nozzle or both (Bambu spec sheet: https://www.solidprint3d.co.uk/wp-content/uploads/2026/04/Bambu-Lab-X2D-3d-printer-specification.pdf).
